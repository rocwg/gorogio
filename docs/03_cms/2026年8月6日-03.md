# （1）公司项目 service 如何选择？

两个方案：

## 方案 A：传统 Spring Service

```text
service

├── ContentService.java
└── impl
    └── ContentServiceImpl.java
```

这是很多 Spring Boot 项目的默认方式。

调用：

```text
Controller

    ↓

ContentService

    ↓

Mapper
```

------

## 方案 B：Application Service

```text
application

├── ContentApplicationService.java
└── impl
    └── ContentApplicationServiceImpl.java
```

调用：

```text
Controller

    ↓

ContentApplicationService

    ↓

Mapper
```

------

## 我的建议（结合你的情况）

我建议：

**公司项目 forestry-cms 采用：**

```text
application
```

不要：

```text
service
```

------

原因不是为了“高级”，而是因为你的模块已经不是简单 CRUD。

你的 CMS 已经存在：

- 发布
- 失效
- 定时发布
- 批量操作
- 权限控制
- 内容资源管理

这些都是：

> 用户意图（Use Case）

而不是：

> 数据操作

------

例如：

传统 Service：

```java
contentService.update(content);
```

表达：

> 更新一条数据

但是业务实际上：

```java
contentApplicationService.publish(ids);
```

表达：

> 发布内容

这是业务动作。

------

所以：

推荐：

```java
public interface ContentApplicationService {


    Long create(ContentCreateRequest request);


    void update(Long id,
                ContentUpdateRequest request);


    void publish(List<Long> ids);


    void offline(List<Long> ids);


}
```

语义更清晰。
