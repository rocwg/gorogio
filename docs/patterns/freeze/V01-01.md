## 1. core

定位：

> Gio 隔离层。

目录：

```text
core
└── gio.go
```

职责：

```go
package core

type Runtime struct {
    // Gio window/frame/op adapter
}
```

未来所有：

```go
gioui.org/app
gioui.org/op
gioui.org/io/event
```

只能出现在这里。

业务永远不知道 Gio。

------

## 2. view ⭐

这是整个体系的核心。

对应：

SwiftUI：

```swift
View
```

Compose：

```kotlin
Composable
```

目录：

```text
view
└── view.go
```

定义：

```go
type View interface {
    Render(ctx Context)
}
```

以后：

```go
view.Text("Hello")

view.Button("Save")

view.Table(data)
```

全部属于这里。

------

## 3. modifier ⭐

保留。

这是最值得抄 SwiftUI 的部分。

目录：

```text
modifier
└── modifier.go
```

概念：

```go
type Modifier interface {
    Apply(View) View
}
```

以后：

```go
view.Text("Hello").
    Apply(
        modifier.Padding(16),
    )
```

或者未来：

```go
view.Text("Hello").
    Padding(16).
    Background(...)
```

------

SwiftUI 的 ViewModifier 本质就是：

> 对 View 应用一个修改，并产生新的 View。

这个思想非常值得借鉴。([Apple Developer](https://developer.apple.com/documentation/SwiftUI/ViewModifier?utm_source=chatgpt.com))

------

## 4. container ⭐

不要叫 layout。

避免：

```text

```

冲突。

对应：

SwiftUI：

```text

VStack
ZStack
```

Compose：

```text
Row
Column
Box
```

目录：

```text
container
└── container.go
```

以后：

```go
container.Row(
    view.Text("A"),
    view.Text("B"),
)
```

------

## 5. style

不要叫 theme。

目录：

这里承载：

------

# （1）core：Gio runtime

您的理解：

> 是不是一个文件占位后，不要加东西；这是当 Gio 官方出现问题的时候需要隔离的时候，再考虑从其它地方提炼、清理？

我的评价：

**方向正确，我甚至建议更激进：v0.1 不要创建 core。**

原因：

现在如果写：

```text
gorogio
└── core
    └── gio.go
```

很容易产生一个幻觉：

> 我已经抽象隔离 Gio 了。

实际上没有。

因为真正的隔离不是：

```go
import "gioui.org/app"
```

包了一层：

```go
gorogio/core/gio
```

而是：

上层代码完全不知道 Gio 存在。

------

Gio 本身的核心模型是：

```text
Window

↓

FrameEvent

↓

layout.Context

↓

op.Ops

↓

Renderer
```

官方文档也是这样描述的：应用通过 `FrameEvent` 更新窗口内容，并把 `op.Ops` 交给窗口驱动。([Gio UI](https://gioui.org/doc/architecture/window?utm_source=chatgpt.com))

所以真正的隔离应该是：

未来：

```go
// 业务层

view.Text("hello")
```

而不是：

```go
func Draw(gtx layout.Context)
```

------

因此我建议：

## v0.1

不要：

```text
core/
```

而是：

```text
internal/
```

例如：

```text
gorogio

├── internal
│   └── gio
│       ├── window.go
│       └── frame.go
```

为什么？

因为：

`internal` 的语义非常准确：

> 这是实现细节，不是公共 API。

------

未来如果 Gio 出问题：

例如：

```
gioui.org
停止维护
```

您做：

```text
internal/gio

↓

internal/gio-fork

↓

internal/renderer
```

即可。

------

所以：

我的修正：

以前：

```
core
```

现在：

```
internal/gio
```

更准确。

------

# （2）app：应用生命周期

这个：

**不完全正确。**

## examples 是什么？

展示：

```text
如何使用 gorogio
```

例如：

```text

├── hello

├── table

```

类似：

Gio 官方也有 example 目录，用于展示使用方式。([Gio UI](https://gioui.org/news/2024-04?utm_source=chatgpt.com))

------

## app 是什么？

app 应该是：

**应用级抽象。**

不是示例。

类似：

SwiftUI：

```swift
@main
struct MyApp: App
```

或者 Compose：

```kotlin
setContent {
}
```

它负责：

```text
Application

↓

Window

↓

Root View

↓

State
```

------

例如：

未来：

```go
func main() {

    app.Run(
        MyApplication{
            Root: Dashboard(),
        },
    )

}
```

这里：

```
app
```

不是业务页面。

它是：

启动框架。

------

所以：

目录应该：

```text
gorogio

├── app
│   ├── application.go
│   └── lifecycle.go
```

而：

```
examples
```

应该另外存在。
