# 那应该抄谁的命名？

我认为：

**不是 Flutter。**

也不是 Gio。

也不是 Material。

最适合您的，其实是：

# SwiftUI + Compose 的思想融合

原因：

SwiftUI 和 Compose 有一个共同核心：

> Declarative UI + Composition + Modifier

SwiftUI：

```swift
Text("Hello")
    .padding()
    .background()
```

Modifier 是官方核心设计之一，一个 modifier 会应用于 View，并产生新的 View 描述。([Apple Developer](https://developer.apple.com/documentation/swiftui/viewmodifier?language=o_4&utm_source=chatgpt.com))

Compose：

```kotlin
Text(
    text = "Hello",
    modifier = Modifier.padding(16.dp)
)
```

Modifier 同样负责：

- layout
- appearance
- behavior
- input

([Android Developers](https://developer.android.com/develop/ui/compose/modifiers?utm_source=chatgpt.com))

这个抽象非常适合 Gio。

## 解释一下

## 1. core

保持。

```text
core
```

职责：

Gio adapter。

里面：

```go
gioui.org/app
gioui.org/op
gioui.org/layout
```

全部隔离。

------

## 2. view ⭐

替代：

```text
components
material
ui
```

我认为这是最重要的调整。

为什么？

因为 SwiftUI：

核心概念：

```text
View
```

不是：

Component。

Apple 官方定义也是：

> View 是表示 UI 一部分，并提供 modifier 配置的类型。([Apple Developer](https://developer.apple.com/documentation/swiftui/view?language=o_11&utm_source=chatgpt.com))

所以：

```go
view.Text()

view.Button()

view.Card()

view.Table()
```

非常自然。

------

## 3. modifier

保留。

这是最值得借鉴 SwiftUI 的地方。

例如：

```go
view.Text("Hello").
    Padding(16).
    Background(style.Primary)
```

------

## 4. container

替代：

```text
layout
```

原因：

避免 Gio layout 冲突。

例如：

```go
container.Row(
    view.Text("A"),
    view.Text("B"),
)
```

类似：

SwiftUI：

```swift
HStack
VStack
ZStack
```

Compose：

```kotlin
Row
Column
Box
```

------

## 5. style

替代：

```text
theme
design
```

为什么？

因为：

theme 太泛。

style 更贴近：

SwiftUI:

```swift
ButtonStyle
LabelStyle
```

Compose:

```kotlin
MaterialTheme
```

您的：

```go
style.Color.Primary

style.Shape.Rounded

style.Type.Title
```

------

## 6. state

替代：

model。

原因：

GUI 世界：

state 是第一语言。

SwiftUI：

```swift
@State
@Observable
```

Compose：

```kotlin
remember
mutableStateOf
```

所以：

```go
state.Store

state.Binding

state.Observable
```

更准确。

------

## 7. pattern

保留。

因为这是您的长期资产。

例如：

```text
├── dashboard
├── data-table

```

## 8. app

保留。

应用入口。

# 为什么我现在认为 SwiftUI 比 Material 3 更适合作为 gorogio 的“母语”？

因为：

Material 3 是：

> 设计系统

不是：

> GUI 编程模型。

Material 告诉您：

- 长什么样；
- 间距多少；
- 圆角多少。

而 SwiftUI 告诉您：

- 怎么组合；
- 怎么表达 UI；
- 怎么扩展。

所以：

关系应该是：

```text
SwiftUI / Compose
        ↓
    编程模型

Material 3
        ↓
    视觉系统

Gio
        ↓
    Runtime
```

您的 gorogio：

应该站在中间：

```text
              App

               ↓

          gorogio

   view + modifier + container

               ↓

             Gio
```
